Hitos 10 y 13: demos y versión

Vas a reconocer el paso desde un programa de pruebas mezcladas a tres demos organizadas, y cómo --version termina antes de ejecutar esas demos.

1. Separar las pruebas por responsabilidad

Cuando todo el código de prueba está junto en main, se mezclan tareas distintas y cuesta localizar qué parte se está comprobando. El hito 10 organiza las pruebas en tres demos: matemática, strings y periféricos simulados. Cada una concentra una responsabilidad; main las coordina.

Organización que refleja el proyecto
MóduloResponsabilidad
demo_math.cEjercicios de funciones matemáticas.
demo_str.cOperaciones sobre strings y CRC.
demo_embedded.cUART simulada, ring, trama y timer.
main.cOrquestar las demos, salvo cuando se solicita versión.

En el flujo normal, el main final invoca cada demo una vez y en orden. Así, el programa conserva las pruebas existentes, pero el punto de entrada deja de contener sus detalles. El hito 10 cambia la organización; no es todavía el modo especial de versión del hito 13.

// src/app/main.c: flujo normal
demo_math();
demo_str();
demo_embedded();

El Makefile del TP incluye el main y los tres archivos src/demo/ entre las fuentes de la aplicación. Las utilidades y módulos HAL se compilan aparte, y con USE_STATIC_LIB = 1 sus objetos se archivan en libutils.a. Cada demo tiene una función propia y main las llama y coordina durante la ejecución; no realiza el enlace, que corresponde a la construcción del ejecutable.

2. Agregar una salida de versión sin cambiar las demos

Un usuario o script puede querer conocer la identidad y versión del ejecutable sin correr las demostraciones. El hito 13 define dos cadenas en main.c y reconoce el argumento --version.

#include <string.h>

static const char PROGRAM_NAME[] = "building-process";
static const char PROGRAM_VERSION[] = "1.0.0";

int main(int argc, char *argv[]) {
  if (argc > 1 && strcmp(argv[1], "--version") == 0) {
    print_str(PROGRAM_NAME);
    print_str(" v");
    print_str(PROGRAM_VERSION);
    print_str("\n");
    return 0;
  }

  demo_math();
  demo_str();
  demo_embedded();
  return 0;
}

PROGRAM_NAME y PROGRAM_VERSION son arrays de caracteres constantes, declarados con alcance de archivo, duración estática y enlace interno por static. No son macros de preprocesador definidas con -D. argc cuenta los argumentos, incluyendo el nombre de invocación en el caso habitual; argv[0] corresponde a ese nombre y el primer argumento del usuario está en argv[1].

La condición argc > 1 asegura que haya una cadena de argumento para comparar. Sin argumentos de usuario, normalmente argc = 1 y argv[1] = NULL, porque argv[argc] es el puntero nulo final: no se debe pasarlo a strcmp. No es que ese elemento del array no pueda consultarse, sino que no apunta a una cadena válida para esta comparación.

strcmp compara el contenido de dos cadenas y devuelve cero cuando son iguales. No se comparan las direcciones de los punteros: dos textos iguales pueden residir en lugares distintos. El && evalúa primero el control de cantidad; si es falso, no evalúa el acceso a argv[1]. Si el argumento coincide, se imprimen nombre y versión y return 0 sale de main, por lo que ninguna demo se ejecuta.

$ ./build/building_process_demo --version
$ strings -a build/building_process_demo | grep building-process

El primer comando ejecuta el programa solicitando la versión; la salida esperada por el código es building-process v1.0.0. El segundo inspecciona el archivo con strings -a, que busca secuencias imprimibles a lo largo de todo el archivo. El pipe | pasa su salida a grep, que conserva las líneas donde aparece building-process. Encontrar el nombre demuestra que la cadena está presente, pero no que la rama se ejecute; para eso se observa la ejecución con el argumento. La búsqueda por defecto de strings puede variar según su configuración, por eso aquí se explicita -a.

3. Seguir los dos caminos de main

Traza conceptual de argumentos
InvocaciónCondiciónCamino
./programaargc no es mayor que 1No lee argv[1]; ejecuta las tres demos.
./programa --versionHay argumento y strcmp devuelve 0Imprime nombre y versión; retorna antes de las demos.
./programa otroHay argumento pero no coincideLa condición falla y sigue el flujo normal de demos.

El cuadro describe el control del código. En la primera fila importa el cortocircuito de &&: la mitad derecha solo se evalúa si existe un argumento de usuario.

Una explicación oral posible

«En el hito 10, las pruebas pasan a tres funciones de demo y main las llama en orden. En el hito 13, dos arrays constantes guardan nombre y versión. Main comprueba primero que haya argumento y luego compara el contenido de argv[1] con --version mediante strcmp. Si coincide imprime y retorna, evitando las demos; en caso contrario ejecuta el camino habitual».

4. Comprobá lo que aprendiste

P1. ¿Qué hace el main en el flujo normal?

Correcta: A. En el camino normal, main orquesta las tres funciones en ese orden. B omite dos demos. C contradice la separación del hito 10. D inventa una llamada obligatoria a versión: la rama ocurre solamente ante el argumento correspondiente.

P2. ¿Cómo están declarados el nombre y versión?

Correcta: A. La fuente declara arrays static const char fuera de funciones: tienen duración estática, alcance de archivo y enlace interno. B confunde arrays con macros -D. C ignora el enlace interno y const. D describe otro origen: las cadenas están definidas en el código.

P3. ¿Por qué se comprueba argc antes de argv[1]?

Correcta: A. Con argc > 1 se sabe que existe argumento de usuario en argv[1]. B no garantiza qué texto contiene. C: strcmp compara contenido. D confunde el nombre de invocación en argv[0] con el argumento.

P4. ¿Qué efecto tiene strcmp y el retorno temprano?

Correctas: A y C. strcmp devuelve cero para contenido igual, no por igualdad de direcciones. El return 0 termina main dentro de la rama, antes de las llamadas a demos. D invierte el orden real.

P5. ¿Qué demuestra la búsqueda con strings -a?

Correctas: A y C. strings -a busca cadenas imprimibles a lo largo del archivo; grep filtra por el nombre. B es falsa: encontrar una cadena no ejecuta ni verifica la rama. D confunde inspección del archivo con ejecución.
