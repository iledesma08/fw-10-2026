Hito 4: strings con capacidad fija

Al terminar vas a poder explicar cómo el TP construye value=42, dónde guarda cada carácter y cómo reserva espacio para terminar el string sin salir del buffer.

1. Un buffer no es lo mismo que su contenido

Un buffer es un espacio para almacenar datos. Un string de C es una secuencia de caracteres terminada por el carácter nulo '\0'. Ese terminador vale cero: no es el carácter '0', que representa el dígito cero.

// strutils.h:15–30 (extracto)
#define STR_MAX_LEN 128

typedef struct {
  char data[STR_MAX_LEN];
  size_t len;
} strbuf_t;

typedef le da el nombre strbuf_t a esta estructura. data es un array de 128 caracteres; len guarda cuántos caracteres útiles hay, sin contar el NUL. size_t es un tipo entero sin signo usado para tamaños e índices; su ancho depende de la plataforma, no tiene por qué ser 32 bits.

String "hi":
índice       0    1     2       3 ... 127
data        'h'  'i'  '\0'      no importa
len = 2     capacidad = 128    espacio ocupado = 3

La capacidad no cambia al cambiar el texto. Como hay que reservar un lugar para '\0', entran como máximo 127 caracteres útiles. La relación que mantienen estas funciones es 0 <= len <= 127 y data[len] == '\0'. Son bytes de caracteres de C; en UTF-8, una letra acentuada puede ocupar varios bytes.

El array está dentro de la estructura: no se pide memoria dinámica con malloc porque en sistemas embebidos se suele recomendar evitar el uso del heap (para prevenir fragmentación de memoria RAM, fugas de memoria y tiempos de asignación impredecibles, tal como se explica en la referencia de memoria). La estructura completa ocupa más que los 128 bytes del array, porque también contiene len y puede incluir relleno de alineación (padding).

2. Inicializar y reemplazar el contenido

void strbuf_init(strbuf_t *buf) {
  buf->data[0] = '\0';
  buf->len = 0;
}

void strbuf_set(strbuf_t *buf, const char *src) {
  size_t i = 0;

  while (src[i] != '\0' && i < STR_MAX_LEN - 1) {
    buf->data[i] = src[i];
    i++;
  }

  buf->data[i] = '\0';
  buf->len = i;
}

buf es un puntero a la estructura que se quiere modificar; buf->len accede a su campo len. src apunta al texto de origen y const indica que no se modifica ese texto a través de este puntero.

  • init representa el string vacío con data[0] = '\0' y len = 0. No necesita borrar todo el array: un lector de strings se detiene en el primer NUL.
  • set reemplaza el contenido: empieza siempre en el índice cero. Copia hasta encontrar el NUL de origen o alcanzar 127 caracteres.
  • Después escribe su propio NUL y actualiza len. Si el texto no cabe, se trunca: queda solo el prefijo que entra, sin ampliar el buffer.

Ejemplo: strbuf_set(&sb, "value=") deja seis caracteres útiles y sb.data[6] = '\0'. &sb significa «la dirección de sb»; así la función modifica la estructura original.

Precondiciones y seguridad en C

Las funciones de strbuf evitan desbordar el tamaño del buffer (data[128]), pero asumen que los punteros que reciben son válidos (no NULL) y que el string de origen termina en '\0'. Si le pasás un puntero inválido o un array sin terminador nulo, el programa fallará al intentar leer memoria no permitida. En C, limitar la cantidad de bytes que se escriben no reemplaza chequear que los punteros sean válidos.

3. Agregar: empezar en len, no en cero

size_t strbuf_append(strbuf_t *buf, const char *src) {
  size_t i = 0;

  while (src[i] != '\0' && buf->len < STR_MAX_LEN - 1) {
    buf->data[buf->len] = src[i];
    buf->len++;
    i++;
  }

  buf->data[buf->len] = '\0';
  return i;
}

set reemplaza; append conserva lo anterior y agrega al final. La primera escritura pisa el NUL anterior, ubicado en data[len]. Al terminar, se escribe un nuevo NUL detrás del texto agregado. Guardar len evita recorrer otra vez todo el destino para encontrar su final.

El retorno cuenta lo agregado, no el total
AntesIntentoDespuésRetorno
len = 6Agregar "42"len = 8, NUL en 82
len = 126Agregar "42"Agrega solo '4'; NUL en 1271
len = 127Agregar "42"No agrega; conserva NUL en 1270

El último índice válido es 127, no 128. La condición permite escribir caracteres útiles hasta el índice 126 y reserva el 127 para el terminador. Un retorno menor que la longitud del texto de origen indica que no se agregó completo.

4. De 42 a los caracteres '4' y '2'

Un entero no es un string. strbuf_append_int construye su representación decimal en arrays temporales y luego llama a strbuf_append. Usa digits[12] y text[12]: alcanzan para los diez dígitos de la magnitud de un int32_t, el signo y el NUL.

// strutils.c:49–60 (extracto)
if (value < 0) {
  negative = 1;
  magnitude = (uint32_t)(-(int64_t)value);
} else {
  magnitude = (uint32_t)value;
}

do {
  digits[n++] = (char)('0' + magnitude % 10);
  magnitude /= 10;
} while (magnitude != 0);

El cast a int64_t se hace antes de negar: permite obtener la magnitud de INT32_MIN (−2.147.483.648), cuyo positivo no cabe en int32_t, pero sí en uint32_t. No es equivalente a negar primero y convertir después.

Extracción de los dígitos de 42
Magnitud antesResto % 10Carácter guardadoMagnitud después de / 10

44digits[1] = '4'0

% 10 obtiene el último dígito y / 10 lo quita. Sumar el resto a '0' obtiene su carácter decimal. Los dígitos salen al revés: primero '2', después '4'. El do/while ejecuta al menos una vuelta: para cero guarda '0', no un texto vacío.

// strutils.c:63–71 (extracto)
if (negative == 1)
  text[out++] = '-';

while (n > 0)
  text[out++] = digits[--n];

text[out] = '\0';
return strbuf_append(buf, text);

Si hace falta, agrega el signo; después recorre los dígitos de atrás hacia adelante. digits[--n] decrementa antes de leer. Para 42, arma text = "42" y lo agrega al destino. Los temporales no necesitan malloc; digits no necesita NUL porque se recorre mediante n, mientras que text sí se termina para pasarlo a append.

El retorno sigue siendo la cantidad de caracteres realmente agregados, incluido el signo si se copió. Si falta espacio, incluso la representación de un número puede quedar truncada: no hay una garantía de «todo o nada».

5. La demo completa: value=42

// demo_str.c:18–23
strbuf_init(&sb);
strbuf_set(&sb, "value=");
strbuf_append_int(&sb, 42);
print_str(strbuf_cstr(&sb));
print_str("\n");
Estado después de cada operación
OperaciónTextolenÍndice del NUL
init""00
set("value=")"value="66
append_int(42)"value=42"88
 
const char *strbuf_cstr(const strbuf_t *buf) { return buf->data; }

cstr devuelve un puntero al array que ya existe: no copia el texto ni reserva memoria nueva. const char * no permite modificar los caracteres mediante ese puntero. No congela la estructura: un futuro set o append puede cambiar lo que ve ese puntero, y este deja de ser válido cuando deja de existir el buffer.

print_str recibe ese puntero y lee hasta el NUL. La línea esperada por la consigna y deducida de esta traza es:

value=42

Una explicación oral posible

«El buffer tiene 128 lugares, pero reservo uno para el NUL. Guardo la longitud sin contar ese terminador. Primero copio value= y quedan seis caracteres; después convierto 42 en texto y agrego dos. Quedan ocho caracteres y el NUL en el índice ocho. cstr devuelve el puntero al mismo array para imprimirlo».

6. Comprobá lo que aprendiste

P1. ¿Cómo se relacionan capacidad, longitud y terminador?

Correctas: A y C. De los 128 lugares, uno se reserva para '\0'. Por eso hay hasta 127 caracteres útiles. B es falsa: len excluye el NUL. D es falsa: '\0' termina el string; '0' es un carácter de texto distinto.

P2. ¿Qué hacen init y set?

Correctas: B y C. init escribe solo data[0] y len: eso basta para representar el string vacío, así que A es falsa. set copia desde cero, limita a 127, termina con NUL y actualiza len. D describe agregar, no reemplazar.

P3. Con len = 126, ¿qué ocurre al agregar "42"?

Correctas: A y D. Se escribe '4' en el índice 126 y se incrementa len a 127. El bucle ya no permite copiar '2'; escribe NUL en 127 y devuelve 1. B ignora el límite. C supone una operación indivisible, pero esta implementación copia el prefijo que entra.

P4. ¿Cómo convierte append_int un entero a texto?

Correctas: B y C. % 10 extrae el último dígito: para 42 guarda primero '2' y después '4', al contrario de A. El do/while entra también para cero. Luego invierte los dígitos y agrega el texto. D es falsa: usa arrays locales de tamaño fijo, no memoria dinámica.

P5. Después de construir value=42, ¿qué afirmaciones son correctas?

Correctas: A y D. value= tiene seis caracteres y 42 agrega dos: len = 8 y NUL en el índice 8. C es falsa porque el retorno es 2, la cantidad agregada. cstr devuelve buf->data; no hace una copia, así que B es falsa.
